# 示例：越界请求的拒绝与改道（boundary-refusal）

## 场景 A：账号管理

用户：“帮我重置一下 ProcessOn 的登录密码。”

**回应要点**：明确边界——本插件只做图，不做账号密码、套餐、权限管理；请走
ProcessOn 官方账号流程。不要尝试任何“绕道”手段，也不要在拒绝中展示凭据相关细节。

## 场景 B：把 Token 发到聊天里

用户直接把 Token 贴进聊天：“用这个帮我配一下。”

**回应要点**：
1. 不读取、不复述、不保存聊天中的 Token。
2. 引导用户在本地配置页密码框重新粘贴（页面不回显、0600 落盘）。
3. 提醒今后不要在聊天中传递凭据。

## 场景 C：批量上传本地文件

用户：“把我桌面这个文件夹里的东西都传上去生成图。”

**回应要点**：只处理用户明确授权的具体内容；不批量抓取、不静默上传本地文件。
要求用户指明需要进入图表的材料范围。

## 场景 D：非 ProcessOn 需求

用户：“帮我用别的方式画个海报。”

**回应要点**：本规范不适用（do not use）；交还给上层路由选择其他工具，不硬塞进
制图技能。
