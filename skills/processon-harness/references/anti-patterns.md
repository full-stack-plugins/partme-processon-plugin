# 反模式与正确替代（anti-patterns）

| ❌ 反模式 | ✅ 正确替代 |
|---|---|
| 把用户粘贴到聊天里的 Token“帮忙配置” | 请用户粘贴进本地配置页密码框；聊天只报状态 |
| 把 Token 写进 `.mcp.json` / `.zshrc` 便于复用 | 只存用户级凭据文件；CI 用受控子进程环境变量 |
| 凭据缺失就反复调用生成工具刷屏 | 等配置页完成保存后一次性重试 |
| `tools/call` 失败立刻再发一次 | 先按 `UNKNOWN_WRITE_RESULT` 对账，确认未生成再重试 |
| 把叙述原文直接扔给生成工具 | 先 `processon-prompt` 定结构与图形类型 |
| 架构图只说“画个架构图” | 明确“架构块图 + 禁止 UML 类表” |
| 交付一个图片 URL 就算完成 | 交付可编辑源文件 + 预览 |
| 并行启动多个重绘循环抢时间 | 串行执行，退避有界 |
| 声称能建 Token / 改权限 / 找回密码 | 明确边界：走 ProcessOn 官方渠道 |
| 复读上游原始错误体给用户 | 只转述脱敏后的语义与处置建议 |
| 自动删除用户凭据“清理环境” | 删除必须用户显式请求 |
| 生成失败后悄悄换需求重画 | 先对账、向用户报告事实，再决定下一步 |
