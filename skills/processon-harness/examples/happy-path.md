# 示例：一次完整的架构图交付（happy-path）

## 用户请求

“把我们订单系统的微服务拆分画成架构图，用 ProcessOn，要能继续编辑。”

## 执行

1. **Step 1 凭据**：`processon-setup` check → configured，继续。
2. **Step 2 结构**：`processon-prompt` 打磨——定为“架构块图”，明确禁止 UML 类表；
   节点：网关 / 订单服务 / 库存服务 / 支付服务 / 消息队列 / 数据库；箭头按同步调用
   与异步事件分两类。
3. **Step 3 生成**：走 `processon-diagram`，以 `generate_chart` 产出可编辑图。
4. **Step 4 评审**：`processon-review` 检查结构、可读性、类型正确性——一轮修订
   （缩短两个过长节点文案）后通过。
5. **Step 5 交付**：可编辑源文件 + 预览 + 一句话结构说明。

## 关键纪律体现

- 需求里写死了“架构块图 + 禁 UML 类表”，避免默认画成类表。
- 评审只走一轮（REVISE_ONCE），未陷入无限重绘。
- 交付物含可编辑源文件，不是裸图片链接。
